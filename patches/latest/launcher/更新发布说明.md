# V1.1 更新与 GitHub 发布

启动器界面版本为 **V1.1**，首个内容版本为 **1.1.0**。之后小修复使用 1.1.1、1.1.2 等内容版本，界面仍是 V1.1。旧启动器可以继续启动游戏，没有联网检查或强制更新。

## 手动覆盖

1. 退出游戏、停止服务端、关闭启动器。
2. 将补丁文件夹里面的内容复制到原分发包根目录（`CSXY启动器.exe` 所在位置），覆盖同名文件。
3. 重新打开启动器。不要将整个补丁目录放进分发包作为子文件夹。

补丁只包含改变的程序、规则或资源文件，不含 `server/state`、密钥、个人设置、日志和抓包。第一次升级 V1.1 可直接覆盖；已经是 V1.1 时也可点右上角“更新中心”，选择本地补丁目录，检查后安装。安装会备份原文件，失败会恢复。备份位于 `updates/backups`，其中 `restore.json` 记录原先不存在的文件。

补丁必须按版本顺序使用，更新中心会检查起始版本；手动复制请参照 `补丁使用说明.txt` 的版本范围。当前没有删除文件、跨版本合并升级或 Python 运行环境升级功能，这类变更应单独准备完整升级包。

## 后续修复生成独立文件夹

在开发目录修改完成并验证后，运行：

```powershell
& .\launcher\BUILD_PATCH.ps1 -Notes '本次修复说明'
```

默认将上次发布版本的末位加一；也可指定 `-Version '1.1.1'`。输出目录位于 `output/CSXY_Patch_版本_时间`，不压缩。程序将源文件与 `analysis/releases/latest.json` 上一次发布记录比较，只输出不同文件。`analysis/latest_patch_path.txt` 记录最近补丁位置。发布记录要保留，不能使用游玩后的目录作为新的基线。

生成只是导出发布文件，不会自动修改其他分发包。开发目录版本元数据会同步到生成版本；已有补丁保持原样，修复导出结果时需重新生成。首次建基线可以使用：

```powershell
python .\launcher\build_patch.py --baseline '原始干净分发包目录' --version 1.1.0
```

`res/entities.bag` 内含分发公钥：生成器保留原分发包公钥，更新中心安装时保留目标安装自己的公钥。包含此资源的补丁手动覆盖仅用于同一原始分发包的副本；独立生成的其他密钥分发包请用更新中心。私钥从不进入补丁。

## GitHub（地址未配置时不联网）

最直接的方式是在专门的 GitHub 更新仓库保留补丁原目录结构：

```text
patches/latest/update-manifest.json
patches/latest/launcher/...
patches/latest/server/...
```

只上传已导出的补丁，不上传整个开发目录或朋友存档。将更新中心地址设为：

```text
https://raw.githubusercontent.com/用户名/仓库名/main/patches/latest/update-manifest.json
```

公开仓库可直接下载；本版未实现私有仓库认证。上传清单和它列出的所有文件，保持相对路径与大小写。先上传文件，最后发布清单，避免玩家下载尚未完整发布的补丁。也可放在 GitHub Pages 或其他 HTTPS 静态站点。

如果使用 GitHub Releases，每个清单文件记录可以设置完整 HTTPS `url` 指向对应发布附件；Releases 附件是平面文件名，需给重名文件分别命名。更新中心配置可用 `https://github.com/用户名/仓库名/releases/latest/download/update-manifest.json`。首版不自动上传、不创建仓库。

保留每个历史版本的补丁。如果玩家跳过了中间版本，当前更新中心会提示按顺序升级，可先选择对应历史补丁。当前是手动点击检查、手动点击安装，不在每次开玩时自动检查，也不强制升级。

在线更新地址单独保存在 `launcher/update_source.json`，补丁不会覆盖它。HTTPS 地址由玩家配置，请填写自己的官方发布地址。SHA256 用于检查下载完整性，清单没有额外的签名机制。
